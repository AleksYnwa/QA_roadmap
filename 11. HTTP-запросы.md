#### [HTTP vs HTTPS](https://selectel.ru/blog/http-request/)

**HTTP** – это открытый протокол передачи данных между браузером и сервером. 
**HTTPS** – тот же HTTP, но с добавленными методами шифрования данных и проверки безопасности, то есть защищенный протокол передачи данных.

- Передаваемые по протоколу HTTP данные не защищены, HTTPS обеспечивает конфиденциальность информации путем ее шифрования (обычно с помощью протокола SSL/TLS, что обеспечивает конфиденциальность и защиту данных от перехвата).
- HTTP использует порт – 80, HTTPS – порт 443.

**HTTP-запрос** – сообщения, которые отправляются клиентом на сервер, чтобы вызвать выполнение некоторых действий. Зачастую для получения доступа к определенному ресурсу. Основой запроса является HTTP-заголовок.
#### Из чего состоит HTTP-запрос

• **Стартовая строка**. В строке запроса указывается метод передачи, версия протокола HTTP и URL, к которому должен обратиться сервер.  
Метод HTTP (HTTP Method) – команда серверу, указывает на операцию над ресурсом.  
**• Заголовки**. Заголовки содержат дополнительную информацию (метаданные) о запросе, либо описывают содержимое тела сообщения.  
**• Пустая строка** сообщает, что все метаданные для конкретного запроса (или ответа) были отправлены.  
• **Тело запроса** (опционально) – завершающая часть HTTP-запроса, поддерживается не всеми методами, содержит данные для внесения изменений в БД. Отсутствует, например у **GET, HEAD и DELETE**. А методы **POST и PUT** могут содержать данные для отправки на сервер.

#### 5 основных методов HTTP-запросов и для чего они используются

Это команды определяющие тип операции, которую клиент хочет выполнить с ресурсами на сервере.   
**• GET.** Запрос содержимого ресурса (например, загрузка HTML-страницы) в режиме «только чтение». Параметры запроса передаются только в URL и ограничены по количеству символов используемым браузером.   
**• POST.** Создает новый ресурс (или загружает файлы на сервер) по данным, которые указаны в теле запроса.  
**• PUT.** Создает новый ресурс или полностью заменяет существующий ресурс данными, которые указаны в теле запроса.  
**• PATCH.** Используется для частичного изменения ресурса.  
**• DELETE.** Удаляет указанный ресурс.

**Query-параметры** (или URL-параметры) – это часть URL-адреса, которая передаёт данные серверу в виде пар ключ=значение, разделённых символом `&`. Они начинаются после знака вопроса (`?`) в URL.

> [!tip]+ Важно
> Метод является **идемпотентным**, если повторное выполнение одного и того же запроса (с одинаковыми параметрами) не изменяет состояние системы после первого выполнения.

Проще говоря:
- Если вызвать метод один раз или много раз подряд с одними и теми же данными, результат будет **одинаковым**, и система не изменится после первого вызова.

Примеры идемпотентных методов в HTTP:
- `GET` – получение данных (не меняет сервер).
- `PUT` – обновление ресурса (повторные вызовы не создают новые ресурсы).
- `DELETE` – удаление ресурса (после первого удаления ресурса его уже нет, повторные вызовы не изменяют состояние).

**Неидемпотентные методы** — это методы, которые **изменяют состояние системы при каждом вызове**, даже если запросы идентичны. Чаще всего это методы, которые:

- Создают новые сущности (например, добавляют запись в базу).
- Выполняют операции с накоплением (например, увеличивают счётчик).
- Зависят от внешнего состояния (например, времени или случайных значений).

Примеры неидемпотентных методов в HTTP:
- `POST` – каждый вызов создаёт новый ресурс (например, `POST /users` создаёт нового пользователя).
- `PATCH` (не всегда) – если изменяет часть ресурса, но результат зависит от текущего состояния (например, `PATCH /balance { "add": 10 }` увеличит баланс на 10 при каждом вызове).
#### Основные коды ответов

1хх – Информационные

2хх – Успешные
**200** OK – данные успешно получены
**201** Created – запрос успешный, а данные созданы;
**202** Accepted – запрос принят в обработку, но ещё не завершён (для асинхронных задач, очередей, длительных операций).
**204** No Content – запрос успешен, но в ответе нет тела (например, на `DELETE` или успешное обновление без возврата данных).

3хх – Перенаправления
**301** Moved Permanently – запрашиваемый ресурс переместили в другую директорию навсегда
**304** Not Modified – ресурс не изменился с прошлого запроса (клиент использовал `If-Modified-Since` / `ETag`). Экономит трафик.

4хх – Ошибки клиента
**400** Bad Request – неверно сформированный запрос
**401** Unauthorized – нужно выполнить аутентификацию перед тем, как запрашивать доступ к ресурсу
**403** Access Forbidden – к ресурсу необходимы другие права доступа
**404** Not Found – сервер принял запрос, но по указанному адресу ничего не обнаружил
**405** Method Not Allowed – метод HTTP (GET/POST/PUT/DELETE) не поддерживается для данного URL
**409** Conflict – конфликт текущего состояния ресурса с запросом (например, duplicate при создании уже существующего).

5хх – Ошибки сервера
**500** Internal Server Error – сервер не смог обработать запрос
**502** Bad Gateway – ошибка шлюза, сервера
**503** Service Temporarily Unavailable – сервис временно недоступен
**504** Gateway Timeout – шлюз (например, nginx) не дождался ответа от вышестоящего сервера за отведённое время.
